Grade 08: Computing

4 units across the school year. Each has a worked example, an activity and a standard to meet.

Task, condition and standard

Task

Meet the outcome of every unit in Grade 08 Computing, and keep one piece of evidence for each.

Condition

A 36-week school year, 4 units, a teacher or guide, a learning book or device, and local examples in the local language first with English support.

Standard

Each unit: at least 8 of 10 marks on a short task, with one line of reasoning for each answer. Course pass: no unit at 'Not yet' after one retry, and a pass in SA1 and SA2.

Assessment plan

Formative checks FA1 to FA4 around weeks 6, 12, 24 and 30; summative checks SA1 in week 18 and SA2 in week 36.

unit by unit

4 units with worked examples

Unit 1 Databases and queries Weeks 1 to 11Create

In this unit you work on 'Databases and queries', taught in a way that is with notes, a worked line and a self-mark. The target is clear: create tables and write simple queries. You move from seeing it, to saying it, to doing it alone.

  • See it: watch or try the skill in 'Databases and queries' on a teacher screen or a safe device.
  • Name the parts: write the key words and what each part does.
  • Use it: create tables and write simple queries. Save your work in a named file or folder.
  • Test and fix: run it, find one fault, correct it, and note what you changed.
Worked example. Solved: Table Students: ID, Name, Class. Query: SELECT Name FROM Students WHERE Class = '7B'; lists the names in 7B. Method: Model run for 'Databases and queries'. Goal in one sentence. Plan: list the steps in order before touching the device. Do: follow the plan, saving after each step. Test: try normal input and one unusual input. Fix: change one thing and test again. Share: show a partner and explain it. What a good answer looks like: it works for normal input, steps match the plan, and the learner can explain each part. Online safety rules apply at all times.

Step by step.

  1. Step 1, Create a table: A learner opens a database tool and types: CREATE TABLE students (id INTEGER PRIMARY KEY, name TEXT, grade INTEGER, score INTEGER); The tool replies that the table was created, with four columns and no rows yet.
  2. Step 2, Insert data: He types INSERT INTO students VALUES (1,'Learner 1',8,72),(2,'Learner 2',8,91),(3,'Learner 3',8,65),(4,'Learner 4',8,88); The tool reports 4 rows added. Text values are in quotes, numbers are not.
  3. Step 3, Select all: SELECT * FROM students; shows all 4 rows and 4 columns. The star means every column. The learner checks the output matches what he typed, which verifies the insert.
  4. Step 4, Filter and order: SELECT name, score FROM students WHERE score >= 80 ORDER BY score DESC; returns two rows: Learner 2 91 first, then Learner 4 88. Learner 1 at 72 and Learner 3 at 65 fail the WHERE test.
  5. Step 5, Aggregate: SELECT COUNT(*) FROM students; returns 4. SELECT AVG(score) FROM students; returns 79.0 because 72 plus 91 plus 65 plus 88 is 316, and 316 divided by 4 is 79.
  6. Step 6, Update and check: UPDATE students SET score = 70 WHERE id = 3; changes Learner 3 from 65 to 70. Running AVG again gives 80.25, since the total is now 321 and 321 divided by 4 is 80.25.
  7. Your turn: Table books(id, title, pages) with (1,'Sea',120),(2,'Sky',200),(3,'Sand',80). List books over 100 pages shortest first, and count them. Model answer: SELECT title, pages FROM books WHERE pages > 100 ORDER BY pages ASC; gives Sea 120, Sky 200; adding WHERE pages > 100 to COUNT(*) gives 2.

Activity. About 30 to 40 minutes of class work, then one short practice task for home. Keep evidence: a worked task and a corrected copy.

Standard to meet. Create tables and write simple queries: at least 8 of 10 marks on a short task, with one line of reasoning for each answer.

Unit 2 Programming with functions and lists Weeks 12 to 22Analyse

In this unit you work on 'Programming with functions and lists', taught in a way that is with notes, a worked line and a self-mark. The target is clear: break a task into functions and use lists. You move from seeing it, to saying it, to doing it alone.

  • See it: watch or try the skill in 'Programming with functions and lists' on a teacher screen or a safe device.
  • Name the parts: write the key words and what each part does.
  • Use it: break a task into functions and use lists. Save your work in a named file or folder.
  • Test and fix: run it, find one fault, correct it, and note what you changed.
Worked example. Solved: Python: for i in range(3): print('Hi') prints Hi three times. Blocks: when flag clicked, repeat 10: move 10 steps. For functions: def square(n): return n * n; square(4) gives 16. Method: Model run for 'Programming with functions and lists'. Goal in one sentence. Plan: list the steps in order before touching the device. Do: follow the plan, saving after each step. Test: try normal input and one unusual input. Fix: change one thing and test again. Share: show a partner and explain it. What a good answer looks like: it works for normal input, steps match the plan, and the learner can explain each part. Online safety rules apply at all times.

Step by step.

  1. Step 1, Break the task into parts. Task: report on five test marks. Parts: find the average, find the highest mark and count how many passed with 50 or more. Each part becomes a function, a named block of code that can be reused and tested on its own.
  2. Step 2, Store the data in a list: marks = [56, 72, 45, 88, 67]. Counting starts at 0, so marks[0] is 56 and marks[-1] is 67. marks[1:3] is the slice [72, 45]. len(marks) is 5. A list keeps related values together under one name.
  3. Step 3, Write a function with a parameter and a return value. def average(items): return sum(items) / len(items). Calling average(marks) gives 328 / 5 = 65.6. The word return sends the answer back. The max(marks) built-in gives 88.
  4. Step 4, Write a function with a loop and a decision. def count_pass(items, limit): count = 0, for x in items: if x >= limit: count += 1, then return count. Calling count_pass(marks, 50) returns 4, because 45 is the only mark below 50.
  5. Step 5, Change the list and run the functions again. marks.append(90) adds a sixth mark. Now len(marks) is 6 and average(marks) is 418 / 6 = 69.67. The functions work with the longer list without any rewriting, which is the benefit of breaking a task into functions.
  6. Step 6, Your turn: temps = [21, 25, 19, 30, 24]. Write a function that counts the temperatures above 22, and find the average. Answer: count is 3 (25, 30 and 24), and the average is 119 / 5 = 23.8.

Activity. About 30 to 40 minutes of class work, then one short practice task for home. Keep evidence: a worked task and a corrected copy.

Standard to meet. Break a task into functions and use lists: at least 8 of 10 marks on a short task, with one line of reasoning for each answer.

Unit 3 Web pages with HTML and CSS Weeks 23 to 33Apply

In this unit you work on 'Web pages with HTML and CSS', taught in a way that is with notes, a worked line and a self-mark. The target is clear: style a multi-page site. You move from seeing it, to saying it, to doing it alone.

  • See it: watch or try the skill in 'Web pages with HTML and CSS' on a teacher screen or a safe device.
  • Name the parts: write the key words and what each part does.
  • Use it: style a multi-page site. Save your work in a named file or folder.
  • Test and fix: run it, find one fault, correct it, and note what you changed.
Worked example. Solved: <h1>My page</h1><p>Hello</p><a href='about.html'>About</a>. CSS: p { color: blue; } makes paragraphs blue. Method: Model run for 'Web pages with HTML and CSS'. Goal in one sentence. Plan: list the steps in order before touching the device. Do: follow the plan, saving after each step. Test: try normal input and one unusual input. Fix: change one thing and test again. Share: show a partner and explain it. What a good answer looks like: it works for normal input, steps match the plan, and the learner can explain each part. Online safety rules apply at all times.

Step by step.

  1. Step 1, Plan the site: A learner builds a 2-page site for a class garden club: index.html (home) and about.html (members), plus one shared style.css. Keeping all three in one folder makes links simple.
  2. Step 2, Shared navigation: In both pages she puts <nav><a href="index.html">Home</a> <a href="about.html">About</a></nav> inside the body. Clicking Home or About now moves between the pages from either one.
  3. Step 3, Link the stylesheet: In the head of both pages she adds <link rel="stylesheet" href="style.css">. Without this line the CSS file would be ignored, so every page that wants the style needs it.
  4. Step 4, Write CSS: In style.css she writes body { font-family: Arial, sans-serif; background-color: #f4f4f4; } and h1 { color: #036; } and nav a { margin-right: 12px; color: #0a6; }. Each rule has a selector and property: value; pairs.
  5. Step 5, Check both pages: She refreshes index.html and about.html. Both have a light grey background, dark blue headings, and green links spaced 12 pixels apart. One change in style.css affects both pages, which saves time.
  6. Step 6, Fix an error: The About page is not styled because she wrote href="styles.css" with an extra s. She changes it to style.css, refreshes, and the style appears. Matching the exact file name is vital.
  7. Your turn: Add a third page contact.html with the same style and nav. Model answer: copy the head including <link rel="stylesheet" href="style.css">, add a Contact link in the nav of all 3 pages, and check each page shows the grey background.

Activity. About 30 to 40 minutes of class work, then one short practice task for home. Keep evidence: a worked task and a corrected copy.

Standard to meet. Style a multi-page site: at least 8 of 10 marks on a short task, with one line of reasoning for each answer.

Unit 4 Safe use of artificial intelligence tools Weeks 34 to 36Apply

In this unit you work on 'Safe use of artificial intelligence tools', taught in a way that is with notes, a worked line and a self-mark. The target is clear: use AI tools responsibly and check their answers. You move from seeing it, to saying it, to doing it alone.

  • See it: watch or try the skill in 'Safe use of artificial intelligence tools' on a teacher screen or a safe device.
  • Name the parts: write the key words and what each part does.
  • Use it: use AI tools responsibly and check their answers. Save your work in a named file or folder.
  • Test and fix: run it, find one fault, correct it, and note what you changed.
Worked example. Solved: AI can be wrong. Check one fact from a second source. Never type personal details into an AI tool. Method: Model run for 'Safe use of artificial intelligence tools'. Goal in one sentence. Plan: list the steps in order before touching the device. Do: follow the plan, saving after each step. Test: try normal input and one unusual input. Fix: change one thing and test again. Share: show a partner and explain it. What a good answer looks like: it works for normal input, steps match the plan, and the learner can explain each part. Online safety rules apply at all times.

Step by step.

  1. Step 1, The task: A learner asks an AI tool, 'What is 15 percent of 240?' The tool replies, '15 percent of 240 is 34.' The learner remembers that AI tools can sound confident but still be wrong, so he plans to check.
  2. Step 2, Check by calculation: He works it out himself. 10 percent of 240 is 24 and 5 percent is 12, so 15 percent is 24 plus 12, which is 36. The tool was wrong by 2. Only the calculation can prove the correct answer.
  3. Step 3, Ask it to show reasoning: The learner writes, 'Show your steps.' The tool now says 240 times 0.15 equals 36. A second try with working gives the right result, but he does not trust it until he has also checked it by hand.
  4. Step 4, Check a source claim: The tool says a book called 'The Desert Rain' by a named author proves a fact. The learner searches the school library catalogue and finds no such book. He treats this as an invented source and does not cite it.
  5. Step 5, Protect privacy: The learner was about to paste his full name, home address and a class photo into the tool. He stops, because anything typed may be stored. He removes the personal details and asks only about the maths.
  6. Step 6, Use honestly: His homework is to write about deserts. He uses the AI for ideas, writes the answer in his own words, checks two facts in a trusted encyclopedia, and tells his teacher he used AI for ideas.
  7. Your turn: An AI says the capital of a country is a city you doubt. What do you do? Model answer: check a trusted atlas or government site, trust the match with two reliable sources, and note that the AI was unreliable.

Activity. About 30 to 40 minutes of class work, then one short practice task for home. Keep evidence: a worked task and a corrected copy.

Standard to meet. Use AI tools responsibly and check their answers: at least 8 of 10 marks on a short task, with one line of reasoning for each answer.

levels L1 to L7

Where this course sits on the ladder

Seven slides, one for each level. Step in at your level and move up; credits stack. A level is reached when you can meet its standard, not by age.

Slide 1. L1 Basic: What a computer does

On the slide: L1 Basic · What a computer does

Notes: Name the four jobs of a computer: input, process, output and storage. Notes: use a washing machine or a phone and label each job with a sticky note; no screens are needed. Learners say which part is the input and which is the output.

Slide 2. L2 Awareness: Steps and algorithms

On the slide: L2 Awareness · Steps and algorithms

Notes: Describe an algorithm as ordered steps and put a set of steps in the right order. Notes: cut up the steps for making a sandwich and mix them; learners order them and find what breaks if two swap. Work unplugged. Safe knife use is for an adult only.

Slide 3. L3 Foundation: Code loops and variables (this course)

On the slide: L3 Foundation · Code loops and variables

Notes: Write a short program that uses a variable and a loop to give a predicted output. Notes: for i in range(1,6), print the square of i. The output is 1, 4, 9, 16, 25 and their total is 55. Learners predict the output first, then run and compare. Take breaks to rest eyes.

This course: Grade 08 Computing is at this level. Its units include Databases and queries; Programming with functions and lists; Web pages with HTML and CSS; Safe use of artificial intelligence tools.

Slide 4. L4 Practitioner: Binary and image size

On the slide: L4 Practitioner · Binary and image size

Notes: Apply binary and storage sums to convert numbers and estimate file size. Notes: 45 in binary is 101101, since 32 plus 8 plus 4 plus 1 is 45. A raw picture of 800 by 600 pixels at 24 bits needs 1,440,000 bytes. Learners check by working back from binary to decimal.

Slide 5. L5 Specialist: Network transfer and security

On the slide: L5 Specialist · Network transfer and security

Notes: Analyse how data moves over a network and compare protections against common threats. Notes: a 50 MB file is 400 megabits; at 20 megabits per second the transfer takes 20 s. Learners work out the time on a slower link and list two safe habits for passwords and updates.

Slide 6. L6 Advanced (degree level): Complexity and search

On the slide: L6 Advanced · Complexity and search

Notes: Apply Big O reasoning to compare linear and binary search. Notes: a sorted list of 1,000,000 items needs at most 20 comparisons by binary search, since 2 to the 20 is 1,048,576, instead of up to a million for linear search. Learners trace a search on 16 numbers by hand.

Slide 7. L7 Super expert (postgraduate/expert): Secure system design

On the slide: L7 Super expert · Secure system design

Notes: Evaluate a small system for security risk and design controls. Notes: a 12-character password from 62 symbols holds about 71.5 bits of entropy, since 12 times log2 of 62 is 71.45. Learners rank threats, choose controls, and test only on systems they own or have written permission to test.

Notes: a level is reached when you can meet its standard, not by age. Learners may move up or down a level by subject.

ten locations and global

Localised for your place

Teach in the local language first, with English support. Use local currency, units and examples in every worksheet. Local curriculum and ministry rules are checked before use in a school; Arabic, Islamic, Social and Moral content needs licensed educators and ministry review. Child-safety rules apply for every learner under 18.

India (Bengaluru)

Use INR in money problems; deliver in English, Hindi, Kannada; personal data rule: Digital Personal Data Protection Act 2023; guardian contact for every learner under 18.

Netherlands (Eindhoven area)

Use EUR in money problems; deliver in Dutch, English; personal data rule: EU GDPR (Dutch: AVG), supervised by the Autoriteit Persoonsgegevens; guardian contact for every learner under 18.

UAE (Dubai and Abu Dhabi)

Use AED in money problems; deliver in Arabic, English; personal data rule: Federal Decree-Law No. 45 of 2021 (personal data protection); guardian contact for every learner under 18.

Brazil (Sao Paulo)

Use BRL in money problems; deliver in Portuguese (Spanish and English support); personal data rule: LGPD (Lei Geral de Protecao de Dados); guardian contact for every learner under 18.

Canada (Toronto)

Use CAD in money problems; deliver in English, French; personal data rule: PIPEDA, with provincial rules where they apply; guardian contact for every learner under 18.

United States

Use USD in money problems; deliver in English, Spanish; personal data rule: state privacy laws (for example California), and COPPA for children under 13; guardian contact for every learner under 18.

Singapore

Use SGD in money problems; deliver in English, Mandarin, Malay, Tamil; personal data rule: Personal Data Protection Act (PDPA); guardian contact for every learner under 18.

Australia

Use AUD in money problems; deliver in English; personal data rule: the Privacy Act 1988 and the Australian Privacy Principles; guardian contact for every learner under 18.

Hong Kong (Eastern Asia)

Use HKD in money problems; deliver in Chinese (Cantonese, Mandarin), English; personal data rule: the Personal Data (Privacy) Ordinance; guardian contact for every learner under 18.

Georgia and Israel (Western Asia)

Use GEL or ILS in money problems; deliver in Georgian, Hebrew, Arabic, English; personal data rule: the personal data law of the country where the learner lives; guardian contact for every learner under 18.

Cayman Islands (Caribbean)

Use KYD in money problems; deliver in English; personal data rule: the Data Protection Act; guardian contact for every learner under 18.

Mexico

Use MXN in money problems; deliver in Spanish, English; personal data rule: the federal law on personal data held by private parties; guardian contact for every learner under 18.
